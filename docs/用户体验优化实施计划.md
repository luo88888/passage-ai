> 版本：v1.2 ｜ 日期：2026-08-06 ｜ 状态：待评审
> 关联需求：TODO.md「1.6 用户体验」——

> 2. 重新进入创作页面时，恢复上次创作状态、进度（重点：去创作页观察进度时准确恢复，含流式生成大纲/正文中断点恢复）
> 3. 点击「开始创作」后立即进入创作页面（无需等待标题生成 / 信息采集完成）
>
> 范围说明：**直接访问 `/create` 不自动恢复最近任务，保留现状（新建表单）**；恢复仅发生在「详情页 → 去创作页观察进度（`/create?taskId=`）」场景。

## 一、背景与目标

当前系统在创作链路上的三个体验缺口：

1. **数据采集可视化**：新闻题材在 `research` 节点采集信息后，只发一条 `RESEARCH_COMPLETE` SSE（仅带 `count`），前端只弹一条 toast「已收集 N 条相关新闻」。用户看不到**搜了什么、采到了哪些新闻、每条新闻的来源/时间/摘要/原文链接**，且采集结果只存在于图状态（`collected_news` 文本），**不落库**，完成后不可回看。

2. **点击「开始创作」后不能立即进入创作页**：`startGenerate` 创建任务成功后只订阅 SSE，**不切换 stage**，用户停留在输入表单页，直到 `TITLE_GENERATED` 到达才跳到「选标题」。标题生成（尤其新闻题材要先采集）耗时较长，期间用户看不到时间轴/进度反馈，体验断裂。

3. **去创作页观察进度时无法准确恢复流式状态**：`resumeByTaskId` 已能按 `phase/status` 恢复「标题候选 / 大纲编辑 / 完成」等落库阶段，但**进行中的流式内容无法恢复**——大纲（`AGENT2_STREAMING`）与正文（`AGENT3_STREAMING`）的增量片段只经 SSE 实时推送、**从不落库**（agent 内部局部变量累积，节点结束才写 DB/checkpoint），中途进入观察页时 `outlineRaw / contentRaw / imageUrls` 均为空，只能看到空白占位等后续新片段，之前已生成的部分全部丢失。

本次开发目标：

1. 信息采集过程与结果可视化：采集结果结构化落库，创作页/详情页可查看「搜索词 + 新闻条目列表」，为后续过程级实时展示预留扩展。
2. 点击「开始创作」立即进入创作页：三栏创作视图（时间轴 + 生成区 + 快捷操作）即刻可见，标题生成 / 信息采集在后台推进，通过 SSE 实时接续到「选标题」。
3. **准确恢复创作进度（重点）**：通过「SSE 历史事件持久化 + 断点重放」，在 `?taskId=` 进入创作页时精确恢复到当前阶段——包括**正在流式生成大纲/正文**（重放已推送片段）与正在生成配图的场景；直接访问 `/create` 不自动恢复，保留现状。

## 三、总体方案

### 3.1 数据采集可视化

**核心思路：采集结果本就结构化，把「结构」保留下来。**

- 后端：`research` 节点把 `InformationCollectionResult` 转为结构化 JSON（含 `searchQueriesUsed` + 文章列表），**落库到 `article.researchData`**，同时继续生成供提示词注入的 `collected_news` 文本；`RESEARCH_COMPLETE` SSE 载荷从「仅 count」升级为「count + searchQueriesUsed + articles」。
- 前端：新增 `ResearchPanel` 组件，在创作页（标题确认前的时间轴旁 / 生成中视图）与详情页展示「搜索词 + 新闻卡片（标题/来源/时间/摘要/标签/原文链接）」，可折叠。
- 采集失败仍走现有降级：`count=0` + 空列表，面板显示「本次未采集到信息」，不阻塞流程。

**过程级实时可视化（可选增强，见「七、分阶段实施计划」阶段四）**：通过 LangChain callback 在采集进行中增量推送 `RESEARCH_START / RESEARCH_QUERY / RESEARCH_ARTICLE`，前端滚动展示采集过程。首期不做，避免侵入采集 Agent 内部。

### 3.2 点击「开始创作」立即进入创作页

**核心思路：创建任务成功即切到「生成中」三栏视图，后台推进、SSE 接续，不再等标题/采集完成。**

- `startGenerate` 拿到 `taskId` 后立即 `stage = 'generating'` + `currentStep = 0` + `ensureSse()`：进入三栏创作视图（左时间轴第 1 步「生成标题」高亮 + 中栏「生成标题中」空态 + 右栏快捷操作/统计）。
- 「生成中」空态按阶段细分文案：
  - 非新闻题材、标题未生成：`AI 正在生成标题方案…`
  - 新闻题材、采集未完成：`正在采集新闻资讯并生成标题方案…`（旁侧展示 ResearchPanel「采集中」占位）
  - 正文/配图阶段：沿用现有流式区（`titleResult` / `outlineRaw` / `contentRaw` / 图片）
- 新闻题材 `RESEARCH_COMPLETE` 到达 → ResearchPanel 填充采集结果；`TITLE_GENERATED` 到达 → `stage = 'titleSelect'`（现有逻辑不变）。
- 创建失败（后端返回错误）→ 回退输入态并展示错误，避免用户被「困」在无任务可看的创作页。

### 3.3 去创作页观察进度时准确恢复（含流式中断点恢复）

**核心思路：以 DB 快照定位阶段 + SSE 历史事件重放还原流式中间态。**

- **入口不变**：仅「详情页 → 去创作页观察进度（`/create?taskId=`）」触发恢复；`resumeByTaskId` 按 `phase/status` 定位阶段，**直接访问 `/create` 不自动恢复（保留现状）**。
- **新增 SSE 历史事件持久化 + 断点重放（关键）**：
  - 后端 `SseEmitterManager` 为每个 `taskId` 维护**有界历史缓冲**（内存，消息 + 自增 `seq`）；`send()` 先写历史再投递实时队列。
  - `GET /api/article/progress/{taskId}` 支持 `?after=<seq>`：订阅时先重放 `seq > after` 的历史消息，再续接实时流；SSE 帧带 `id: <seq>`。
  - 前端 `subscribeArticleProgress` 记录最近 `lastEventId`：`resumeByTaskId` 首次订阅 `after=0` 全量重放（`outlineRaw / contentRaw / imageUrls` 等**精确还原**）；断线自动重连时带 `after=lastSeq`，避免重复追加。
- **恢复矩阵**（`resumeByTaskId`，补齐 PENDING / TITLE_GENERATING 分支）：

| DB phase / status | 恢复动作 |
| --- | --- |
| PENDING / PENDING | 进入「生成中」视图（预标题空态）+ 订阅 SSE（`after=0`，start 任务异步推进中，事件到达即展示） |
| TITLE_GENERATING / PROCESSING | 进入「生成中」视图（预标题空态）+ 订阅 SSE（重放可能已发的 `RESEARCH_COMPLETE` / `TITLE_GENERATED`，到点自动切「选标题」） |
| TITLE_SELECTING / PROCESSING | 展示 `titleOptions` 候选（DB 已落库），等待确认（不连 SSE） |
| OUTLINE_GENERATING / PROCESSING | 展示已确认标题 + 「编辑大纲」占位 + 订阅 SSE（**重放 `AGENT2_STREAMING` 还原流式大纲**，`OUTLINE_GENERATED` 到点切编辑器） |
| OUTLINE_EDITING / PROCESSING | 展示大纲编辑器（DB 已落库，含 AI 修改） |
| CONTENT_GENERATING / PROCESSING | 展示已确认大纲 + 「生成中」流式区 + 订阅 SSE（**重放 `AGENT3_STREAMING` / `IMAGE_COMPLETE` 等还原已生成正文与配图**） |
| COMPLETED | 直接展示结果（done） |
| FAILED | 展示错误信息 + 允许重新创作 |

**恢复保真度边界（本期接受，见「九、风险」）**：历史缓冲为进程内存，后端进程重启后任务本身已中断（无任务恢复机制），流式中间态不可再恢复；`CONTENT_GENERATING` 阶段正文终态仍以 finalize 落库为准。

## 四、数据库设计

新增迁移脚本：`backend/sql/add_research_data.sql`（增量，可重复执行需幂等）。

```sql
-- 信息采集结果（数据采集可视化）：文章表新增一列，JSON 存储结构化采集结果
ALTER TABLE article
    ADD COLUMN researchData JSON NULL COMMENT '信息采集结果（JSON）：{requirement, searchQueriesUsed, articles[]}' AFTER enabledImageMethods;
```

数据结构（与 `InformationCollectionResult` 对齐，字段用 camelCase 与既有 JSON 列习惯一致）：

```json
{
  "requirement": "请采集与以下新闻主题相关的最新报道与事实信息：xxx",
  "searchQueriesUsed": ["2026年 AI 职场", "AI 就业趋势"],
  "articles": [
    {
      "title": "《...》",
      "url": "https://...",
      "summary": "基于全文内容的摘要（≤500字）",
      "publishTime": "2026-6-26",
      "source": "媒体名称",
      "author": "作者",
      "tags": ["AI", "就业"]

```

ORM 映射沿用现有惯例（DB 用 JSON、ORM 用 Text，同 `outline`）：`backend/app/models/article.py` 增加 `research_data = Column("researchData", Text, nullable=True, comment=...)`。

### 5.2 SSE 历史事件持久化 + 断点重放（创作进度准确恢复）

1. **`backend/app/managers/sse_manager.py`**（核心改造）：
   - 新增每任务历史缓冲：`self._history: Dict[str, List[str]]`，`self._seq: Dict[str, int]` 自增序号；
   - `send(task_id, message)`：先追加到 `_history[task_id]`（带序号，**有界**：如 `maxlen=2000` 或按总字节数截断，超限丢最旧），再 `put_nowait` 到实时队列；
   - `create_emitter(task_id, after_seq: int = 0)`：新建队列后先把 `_history` 中 `seq > after_seq` 的消息依序 `put_nowait`，再进入实时循环；SSE 帧格式升级为 `id: <seq>\ndata: <json>\n\n`；
   - `complete(task_id)`：发 `__COMPLETE__` 后清理队列与历史缓冲（释放内存）；`exists()` 语义不变。

2. **`backend/app/routers/article.py::get_progress`**：读取可选查询参数 `after: int = 0`，透传给 `create_emitter(task_id, after)`（`after` 做 `>=0` 校验）。

3. 顺序与去重保证（消费语义，而非物理去重）：`send()` 对每条消息先追加历史缓冲（可重放副本）、再投递实时队列（投递通道）——同一 `seq` 的消息**可能同时存在**于历史与实时队列两处。真正保证「不重不漏」的是：
   - 每个 task 内 `seq` 全局单调递增；
   - 前端以「已收到的最新 `seq`（after）」订阅，服务端只重放 `seq > after` 的历史消息，订阅建立后到达的新消息走实时队列；
   - `create_emitter` 在**同步代码段内**完成「回放历史 → 注册实时队列」（无 await 间隙），以订阅时刻为界：订阅前的事件只经重放路径送达、订阅后的事件只经实时路径送达，故每个 `seq` 恰好被前端消费一次。
   边界竞态：若 `send()` 发生在注册实时队列之前，消息只进历史、由重放送达；若发生在注册之后，消息进历史 + 实时队列，但重放已完成，只会经实时路径送达——两种情形均不重复、不乱序。

### 5.3 前端 API 客户端与 SSE 工具

- `frontend/src/utils/sse.ts`：`subscribeArticleProgress(taskId, handlers, options?: { after?: number })`，URL 追加 `?after=`；每条消息记录 `ev.lastEventId`（`lastSeq`），返回句柄暴露 `getLastSeq()` 供重连使用。
- 说明：openapi2ts 因 `/api/v3/api-docs` 路径缺失无法生成新接口（现有注释已说明），本期无新增业务接口（`/recover` 已取消），SSE 改造全部在 `sse_manager` / `sse.ts` 内完成，不涉及 `articleController.ts`。

   若 `createArticle` 返回错误 → 保持/回退 `input` 阶段并展示 `errorMsg`（现逻辑已有，补 stage 回退）。

2. 「生成中」空态细分（模板 `.empty-streaming`）：
   - 用 computed 区分「标题生成中」与「正文生成中」：`isPreTitlePhase = stage==='generating' && !titleResult && !outlineRaw && !contentRaw && !imageCount`；
   - 文案：`isNewsGenre && researchLoading` → `正在采集新闻资讯并生成标题方案…`；`isPreTitlePhase` → `AI 正在生成标题方案…`；其余沿用「AI 正在构思中…」；
   - 左侧时间轴第 1 步在 `currentStep===0` 时显示 `LoadingOutlined`（现有 `.timeline` 逻辑已支持）。

3. `TITLE_GENERATED` 到达 → `stage='titleSelect'`（现有 `handleSse` 不变），此时 ResearchPanel 已在页面上展示采集结果。

### 6.3 去创作页观察进度时准确恢复（`?taskId=`）

**`frontend/src/pages/article/CreateArticlePage.vue` + `frontend/src/utils/sse.ts`**：

1. `resumeByTaskId` 保持「仅 `?taskId=` 触发」的现状，不做 `/create` 自动恢复；补充/调整分支：
   - **PENDING 分支**：`stage='generating'`（预标题空态）+ `ensureSse()`（订阅 `after=0`）；
   - **TITLE_GENERATING 分支**：由 `stage='titleSelect'` 改为 `stage='generating'`（预标题空态）+ `ensureSse()`，与「立即进入创作页」体验统一；
   - 其余分支（TITLE_SELECTING / OUTLINE_GENERATING / OUTLINE_EDITING / CONTENT_GENERATING / COMPLETED / FAILED）沿用现有逻辑，仅把 `ensureSse()` 改为带 `after=0` 的首次订阅。
2. **流式还原**（核心）：`ensureSse()` 订阅时传 `after = 0`（首次进入全量重放）；收到重放的 `AGENT2_STREAMING / AGENT3_STREAMING / IMAGE_COMPLETE` 后，`outlineRaw / contentRaw / imageUrls` 依序追加/还原，页面呈现与「一直在场」一致的中间态；`OUTLINE_GENERATED / TITLE_GENERATED / AGENT5_COMPLETE / MERGE_COMPLETE` 等覆盖式事件按现有 `handleSse` 幂等处理。
3. **断线续传**：`ensureSse` 的重连逻辑改为携带 `after = getLastSeq()`（`sse.ts` 提供），避免同会话断线重连时重复追加已收到的流式片段；`resumeByTaskId` 页面级进入与同页断线重连两种路径均覆盖。
4. **恢复提示**：进入恢复时（`?taskId=` 且任务进行中）顶部展示轻量提示条「正在恢复创作进度 · 任务ID · 放弃恢复」，样式与现有 `error-banner` 一致；「放弃恢复」复用 `resetAll` 回到干净输入态。

## 八、验收标准

**数据采集可视化**

1. 新闻题材创建文章，创作页可见采集面板：搜索词、N 条新闻卡片（标题/来源/时间/摘要/原文链接）。
2. 采集失败或 0 条时面板显示空态，不阻塞后续生成。
3. 文章完成后，详情页可回看同一份采集结果。
4. 非新闻题材不触发采集、不显示面板。

**点击「开始创作」立即进入创作页**

5. 点击「开始创作」后页面**立即**切换到三栏创作视图（左侧时间轴可见、第 1 步「生成标题」高亮），无需等待标题生成完成。
6. 新闻题材创建时，创作页即时展示「信息采集中…」占位，采集完成后回填采集面板；标题生成完成自动进入「选标题」阶段。
7. 创建接口失败时回到输入态并展示错误，不出现「无任务可看的创作页」。

**创作进度准确恢复（`?taskId=`）**

8. 直接访问 `/create` 不自动恢复，行为与现状一致（新建表单）。
9. 详情页「去创作页观察进度」进入：按 phase 恢复到正确阶段（TITLE_SELECTING→标题候选；OUTLINE_EDITING→大纲编辑器；CONTENT_GENERATING→流式区并重连 SSE；COMPLETED/FAILED→结果/错误）。
10. **流式进行中进入可准确还原**：大纲生成中（`AGENT2_STREAMING`）进入 → 展示已流式生成的大纲文本并继续实时追加；正文生成中（`AGENT3_STREAMING` / `IMAGE_COMPLETE`）进入 → 展示已生成的正文与已完成的配图并继续实时推进。
11. 同页 SSE 断线自动重连后不重复追加已收到的流式片段（`after=lastSeq` 生效）。
12. 标题/大纲确认后流程可正常走完，终态与 SSE 重放无冲突。

## 九、风险与注意事项

1. **历史缓冲为进程内存**：后端进程重启后流式历史丢失；但重启后生成任务本身也已中断（无任务恢复机制，独立遗留项），两者一致。可选阶段四落 Redis 加固。
2. **历史缓冲内存占用**：流式片段多、任务并发大时占用内存——需有界（条数/字节上限）并在 `complete()` 时清理；可在 `send()` 里对超限任务截断最旧消息。
3. **重放与实时顺序（实现前提）**：`create_emitter` 的「回放历史 → 注册实时队列」必须在同步代码段完成（或加 per-task 锁），否则 `send()` 可能在回放中途插入新消息造成乱序/重复；多订阅者/Redis 化时需保证同 `taskId` 消息全局有序。
4. **重放事件幂等性**：`handleSse` 对覆盖式事件（TITLE_GENERATED / OUTLINE_GENERATED / AGENT5_COMPLETE / MERGE_COMPLETE）天然幂等；追加式事件（STREAMING / IMAGE_COMPLETE）依赖「首次进入清空累加器 + after 续传」保证不重复，需在 3.4 落实。
5. **`CONTENT_GENERATING` 阶段正文终态未落库**：finalize 才写全文；若在正文生成中进入并随后任务失败，正文草稿仅存在于前端重放，最终以 DB 终态/失败提示为准。
6. **「立即进入创作页」与创建失败的时序**：`createArticle` 成功后立即切 stage，若任务实际未启动（如服务异常），页面可能长时间停在「生成标题中」空态——由 `ensureSse` 的断线重连/超时提示兜底；创建接口返回失败则必须回退输入态。
7. **SSE 帧格式变更**：新增 `id:` 行不影响旧客户端解析（`EventSource` 兼容）；但 `get_progress` 增加 `after` 参数后，旧前端不带参数仍可工作（默认 `after=0` 全量重放）。
8. **前端类型联调**：`ArticleVO.researchData` 需同步到 `frontend` 侧类型（`API.ArticleVO` / sse 类型），避免 TS 编译报错。
9. **阶段联动**：阶段二依赖阶段一的 `ResearchPanel`（含 loading 态）展示采集进度；阶段三的 TITLE_GENERATING/PENDING 分支依赖阶段二的「生成中」预标题视图；实施顺序建议 一 → 二 → 三。
